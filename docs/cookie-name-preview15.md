# preview.15 · 饼干名称只读

日期：2026-10-25。根据用户反馈，饼干名称属于导入内容，不应作为可修改的备注。

## 界面与保存规则

- “备注名称”改为“饼干名称”，使用普通文本显示，不提供编辑框。
- 二维码、剪贴板与 JSON 文本导入均使用其中的 `name`。选择另一张二维码或修改导入内容时，立即重新显示对应名称，不沿用上一份内容的名称。
- 新饼干的导入内容没有名称时，使用默认名称“饼干 N”；输入为空或尚未有效时显示“—”。
- 重复导入复用已有身份。有源名称时同步该名称；只有 userhash 的重复导入保留已有名称。名称与认证值一同解析，保存时不从界面文字获取名称。
- 当前身份、列表和重启后的名称保持一致。已有数据不主动改名；订阅号的备注功能保持原有行为。

二维码识别结果以 JSON 形式暂存在隐藏的饼干内容框内，避免独立保存名称而造成错配；保存到资料目录时仍只保留 DPAPI 加密的凭据及名称，完成导入或关闭窗口后清空输入。

## Skill 与验证

沿用 `ui-ux-pro-max` 的表单语义、可见标签及浅色/深色一致性原则：不可编辑的信息使用文本，不使用禁用的灰色输入框冒充只读名称。

扩展现有 `CookieImportChecks` 检查：名称没有编辑控件、二维码更换、改为无名称文本、JSON 名称、重复导入名称同步及重启保存。继续验证二维码、加密保存、认证请求和异常输入。最终 EXE 另通过 UI Automation 检查名称是可见文本且已移除备注输入框。实际执行结果见 [交付验证](verification.md)。

## 用户验收

打开 `release/0.2.0-preview.15/Tide.exe`，在“饼干管理”选择二维码：名称应显示为导出内容里的名字，无法手动编辑；点击“导入并使用”后，当前名称与列表一致。
