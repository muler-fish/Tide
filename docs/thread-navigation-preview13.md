日期：2026-10-24。状态：实现完成，待用户验收；第 3 项未划掉。第 2 项已获用户明确验收并在 TODO 中划掉。新增的 emoji、悬浮按钮参考图、操作反馈气泡要求保留原文，按清单逐项处理。

## 操作

- 底部输入页码，按回车或点击“跳转”。目标页大于 1 时，只显示该页回复，不重复插入串首。
- 跳到中间页后，向上滚动到顶部加载上一页；向下滚动到底部加载下一页。跳转后没有滚动操作时，不自行加载相邻页。
- 只有加载到第 1 页时才显示主楼。标题、PO 身份及回应目标仍使用当前串的信息。
- 加载前页时，保留眼前回复的位置；请求等待期间可以继续阅读，响应返回时才记录并还原当前可见项的位置。
- 顶部细条表示前页加载，失败时显示“重试上一页”；向下续载继续使用底部加载反馈和重试。两端请求串行，不自动反复重试失败页。
- 加载期间仍可跳页；连续跳页以最后一次为准，较早的响应不会覆盖新结果。
- 页码框是待跳转页，旁边显示已加载页范围。后台续载不会改写正在输入的数字。
- PO 筛选也可从没有匹配回复的中间页向前寻找；输入不合法或超出已知总页数时保留正文并显示错误。

## 诊断及 Skill

修复前退出码 1，失败信息：`跳到第 5 页后仍首先显示串首，没有从目标页回复开始阅读。`
`jump-observation.json` 记录请求页 `[1,5]`、输入 `5`、范围 `第 5 / 10 页`，但第一项是主楼 ID `1000`、主楼数量 `1`。因此请求抵达正确页，显示与导航状态是本次问题所在。

按以下三个方向核对，并分别加入检查：

1. 显示集合强制插入主楼：`RebuildReading` 原来无条件添加主楼。改为加载范围包含第 1 页时添加。
2. 忙碌时跳转被忽略：原命令条件禁止 ThreadBusy 时执行，同一 TaskCommand 也禁止重入。跳页命令现在允许重入，由正文请求的取消源和版本号保证最后一次生效；发帖等其他命令仍保持互斥。
3. 续载覆盖输入：旧实现每次结果到达都写 PageText。现在仅开始显式打开/跳页时写入，后续追加和前插不覆盖草稿输入。

同时使用 `ui-ux-pro-max` 核对滚动、加载反馈和键盘操作：保持原有三栏和 WPF UI 控件；新增可见“跳转”按钮；加载条与前页重试覆盖在阅读区边缘，不改变阅读视口高度；前插期间先停止惯性，再恢复锚点，避免两个位置控制互相争夺。

## 代码结构

- `MainViewModel.cs`：按替换、前插、追加处理返回内容，独立维护已加载起始页和末页。显式导航保留取消及版本检查。
- `MainViewModel.IncrementalLoading.cs`：上一页命令、独立失败状态；按帖子 ID 去重，空页或全重复页停止该方向。PO 过滤后只插入可见项。
- `IncrementalScroll.cs`：上一页命令和滚动方向检测。跳转后等用户输入；向上只检查顶部，向下检查底部。保留 90 ms 节流和原生虚拟化。
- `ReadingAnchor.cs`：在提交前页时记录首个可见项及像素坐标；前插后根据真实容器坐标纠偏，避免依赖所有楼层的估算高度。只操作附近已实现的控件。
- `MainWindow.xaml.cs`：连接前插前后事件、锚点恢复和直接跳页的回顶动作。
- `MainWindow.xaml`：页码框、跳转按钮、顶部前页加载与重试。
- `ThreadNavigationChecks.cs`：模拟页面及慢响应，用真实窗口、键盘和自动化按钮检查整条交互路径。
