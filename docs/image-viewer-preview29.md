# 图片加载与独立看图窗口 · preview.29

后续更新：preview.30 已增加末图自动续页，当前行为见 [续页说明](image-viewer-preview30.md)。下文保留 preview.29 当时的实现范围。

本轮对应 TODO 第 8 项（原 11），待用户验收。第 7 项已获确认并归档。实现采用用户选择的独立窗口，布局参照随后提供的 QQ 截图，并按最新反馈移除“更多”按钮。

## 界面与操作

- 看图窗口固定深色画布，保留 WPF UI 标题栏和窗口控制；主程序阅读主题不受影响。系统高对比度下采用系统画布与文字颜色。
- 左右圆形按钮切换上一张、下一张；首尾禁用相应按钮，不循环跳转。标题栏显示当前发言串号及图片序号。
- 底部按缩小、当前比例、放大、1:1、旋转、保存排列。缩放三项组成一组，其余等宽分布；小窗口保持同一行。
- 滚轮以指针位置缩放，按住鼠标左键拖动；小图居中，大图限制拖动边界。双击或 1:1 按钮切换原始比例与适应窗口。
- ← / → 切图，+ / − 缩放，1 原始比例，0 适应窗口，R 向左旋转 90°，Esc 关闭。图标均有悬停说明、键盘焦点和辅助技术名称。
- 旋转只影响显示；“保存原图”始终保存下载的原始文件字节。

## 图库范围和加载

从串阅读区点击图片时，收集当前已加载并显示的带图发言，按阅读顺序组成快照；启用“只看 PO”时只含当前显示范围。不额外翻页，也不预先下载其他原图。看图期间继续阅读或切换串，不改变已打开窗口的图库；重新打开图片可取得新的范围。从串列表或引用弹窗打开时只查看该图片。

缩略图及原图下载期间显示动态进度；Windows 关闭界面动画时使用静态占位。加载失败可重试，无图模式保留手动查看入口。原图解码失败时仍可保存已下载的原文件。解码移到后台，界面保持可切图和关闭。

原图窗口最多缓存三张原始文件，总量不超过 32 MiB；只驻留内存，关闭窗口释放。缩略图沿用独立的最多 80 项内存缓存。返回已经看过的原图可免重复下载；切图和关闭取消旧请求，使用代次检查防止迟到结果覆盖新图，失败重试清除当前坏图缓存。

GIF 仍显示首帧，标题栏提示这一点；本轮没有引入新的动图解码依赖。保存的 GIF 原文件保留动画。当前看图窗口没有更多菜单。

## 技能与设计依据

沿用 `ui-ux-pro-max`。本轮以 `image loading feedback desktop --domain ux` 查询，结果为 Loading Indicators、Loading States、Image Optimization，适用于现有 WPF 桌面控件。采用明确加载状态、局部失败重试、后台解码和可取消操作；不重新生成整套设计系统。

## 实现位置

- `src/Tide.Desktop/ImageService.cs`：图片下载、缩略图内存缓存、加载占位和控件复用时的请求取消。
- `src/Tide.Desktop/ImageWindow.cs`：图库快照、临时缓存、原图异步加载、缩放/拖动/旋转和原文件保存。
- `src/Tide.Desktop/ImageViewerResources.xaml`：局部深色主题、底栏图标按钮、两侧圆形按钮及交互状态。
- `src/Tide.Desktop/MainWindow.xaml.cs`：根据图片控件所在区域选择图库范围。
- `tests/Tide.Desktop.Tests/ImageViewerChecks.cs`：使用固定图片和可控慢请求检查加载、切图、竞态、缓存、失败重试、无图模式、比例与拖动边界、旋转和关闭取消。

## 验收

1. 打开一个包含多张图片的串，点击串阅读区图片，左右切换；关闭窗口后仍在原阅读位置。
2. 滚轮缩放、拖动，点击 1:1/适应按钮和旋转按钮；调整窗口大小后检查图片和底部工具是否完整。
3. 返回刚看过的图片，确认不用再次下载；图片加载失败时点击重试。保存一张图片，确认文件保持原格式。
4. 分别在主程序浅色、深色模式下进入看图窗口，确认画布保持深色，标题栏和工具按钮可辨认。
