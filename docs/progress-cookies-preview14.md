## 本轮行为

- 阅读进度保存实际可见的回复、所在页、回复内偏移和 PO 筛选状态。滚动期间最多约每 750ms 保存一次，切串、切换身份和正常关闭窗口前补存。
- 重新打开已读串时恢复位置；刷新保留位置；显式输入页码时以新页为准。后台加载下一页或前插上一页不等于已经读到那里。
- 旧记录只有页码时回到该页顶部；原回复被删除时回到同页相近回复。恢复后用户滚轮、鼠标或键盘操作立即结束位置锁定。图片或字号变化可使最终像素位置略有差异。
- 页码框首次点击或键盘聚焦全选；再次点击、拖选、双击和右键操作继续由原生控件处理。扩大输入区域，使用 `TextAlignment` 居中文本，内容宿主保持铺满输入框。
- 饼干管理首屏提供“选择二维码图片”“粘贴二维码”。支持 PNG/JPG 等系统解码图片、剪贴板图片、完整 userhash、Cookie 头及二维码 JSON。识别后点击“导入并使用”；显示当前备注名称。重导同一饼干复用已有身份。
- 二维码在本机工作线程解码，完整凭据继续用 PasswordBox 输入、Windows DPAPI 加密保存。识别失败、关闭识别窗口、保存失败不会提交新身份。导入成功立即更换后续请求的 Cookie；关闭管理窗口后重新打开刚才的串。

## 大串问题的证据与边界

公开案例：[No.51288554](https://www.nmbxd1.com/t/51288554)。2026-10-24 对未携带饼干的 HTTPS GET 实测：ReplyCount 为 8995，按每页 19 条为 474 页。第 100、200、400、474 页都返回相同的 19 条有效回复，首尾 ID 为 `55499780` / `55525229`，日期为 2023-02-11 至 2023-02-12。第 99 页首尾不同。小写 / 大写 Api 及路径式参数也复现重复。记录在 `artifacts/large-thread-probe/api-pages-before.json`。

网页版 `?page=474` 的底部页码显示 474，但取得的回复链接包含 `page=100`，实际内容也与第 100 页一致。因此不能用底部数字作为跳页成功证据。主站 `/Api/thread` 探测返回 HTTP 503，未确认它可作为替代数据源；不会静默切换到这个端点。

用户确认手机、网页能查看高页，且两端均已导入饼干。**登录身份是待核验的差异，尚未使用真实饼干证明因果关系。** 所查 [霞岛接口构造](https://github.com/orzogc/xdnmb_api/blob/28fdba53031a15e0de88954679afe91b9308f71a/lib/src/urls.dart) 同样使用 `Api/thread` 的 id/page 参数；没有足够依据宣称需要另一套新版分页 API。

当前处理：对大于 100 的返回页，与同一身份下第 100 页的有效回复 ID 序列核对。完全重复则报错并保留原正文、原进度，不保存错误页；提示游客先导入有效饼干，已有身份则检查有效性。内容不同的高页照常支持，没有添加客户端 100 页上限。基准最多缓存 40 串 / 30 秒，身份切换立即清理，正常高页不会每次都额外请求基准。错误检查也适用于上下续载，失败后显示重试。

旧版可能把第 100 页存为第 200 页，因此不再使用未校验的旧高页离线缓存；文件保留，正常低页缓存不受影响。验证过的新高页仍可离线读取。这里的校验针对本次实测的第 100 页重复，不是对任意服务端错页的普遍保证。

## Skill 与诊断过程

使用 `diagnosing-bugs` 与 `ui-ux-pro-max`。保持既有三栏与 WPF UI，关注焦点、加载反馈、位置连续性；没有换主题。

实际 WPF 红灯复现：

```powershell
.\tests\Tide.Desktop.Tests\bin\Release\net10.0-windows\Tide.Desktop.Tests.exe --reading-progress artifacts/progress-preview14-before
.\tests\Tide.Desktop.Tests\bin\Release\net10.0-windows\Tide.Desktop.Tests.exe --thread-navigation artifacts/page-input-preview14-before
```

前者在第 2 页阅读时后台加载第 3 页，原实现把历史改为 3；后者首次点击页码框没有全选。修复后的同路径检查通过。恢复测试还捕获了旧回顶请求与恢复偏移竞争，现已避免二者同时执行，并按布局变化有限纠偏。

对长串依次排查接口截断、参数格式和客户端接口差异。真实 HTTP 对比先复现；随后用同样的重复 ID 响应建立回归检查，原实现不报错，修复后拒绝错误页。另以合成 Cookie 模拟身份变化后第 200 页及 199/201 页续载，确认客户端认证与分页链路；这不替代真实账号验收。
