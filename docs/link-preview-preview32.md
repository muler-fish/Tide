# 串预览与板块跳转提示 · preview.32

对应 TODO 第 9 项的交互修订。用户指出直接跳转会打断阅读，本轮以预览和明确确认替代直接导航；第 8、9 项仍待验收。

## 行为

- 正文、tips 或子窗口里的普通串链接先打开“串预览”小窗，展示串首标题、名称（若有）、饼干、时间、回复数、正文及图片。图片遵循当前无图模式，仍可手动打开。
- 预览只读取第一页用于展示，使用已有 30 秒临时页缓存。它不更改当前正文、页码、PO 筛选、列表或阅读历史；关闭按钮、Esc 和标题栏关闭均返回原阅读环境。
- 点击“打开串”才进入主阅读区；链接指定了页码时按钮显示“打开第 N 页”，确认打开后仍保留页码与回复定位参数。顶部跳串输入框继续直接导航，因为这是用户明确输入的跳串操作。
- 预览加载中可直接关闭。失败仅在小窗内提示并提供重试，重试绕过临时缓存；主窗口不会因此出现错误条或跳走。关闭取消请求，迟到结果不会重建小窗。
- 板块或时间线链接先显示“即将跳转到‘婆罗门一’”形式的小窗，提供“取消”和“跳转”；已知板块显示正式名称。目录解析在小窗内进行，不清空当前串列表，也不占用其加载状态。
- 取消、Esc 或标题栏关闭均不导航。点击“跳转”才切换串列表区，右侧原串仍保留。无法在客户端匹配的板块在小窗中说明并提供“浏览器打开”，不自动跳到网页。
- 外站、其他未知网页保持原来的浏览器处理；`>>No.` 保持引用小窗。原有新旧 URL 解析与安全边界不改动。

## 布局与技能

沿用 `ui-ux-pro-max` 中的状态保持、可关闭弹窗和明确导航入口原则。串预览复用现有 DialogWindow、PostBody、PostIdentity、PostImage；板块提示使用紧凑 Fluent 子窗口与系统风格按钮。两者跟随深浅主题，保留标题栏和键盘关闭入口。小窗不会锁住主窗口，用户可继续阅读。

## 实现与验证范围

- `src/Tide.Desktop/LinkWindows.cs`：串首预览、局部加载/错误/重试、打开操作、板块提示与取消。
- `src/Tide.Desktop/MainViewModel.Links.cs`：只读串首和板块名称解析，与主阅读/列表导航分离。
- `src/Tide.Desktop/MainWindow.xaml.cs`：按链接类型打开小窗，维持所属窗口关系。
- `tests/Tide.Desktop.Tests/ContentLinkChecks.cs`：按新交互更新 `--links` 专项。

遵循用户的最小测试要求，仅运行更新后的 `--links`：实际 tips 蓝链触发、板块取消/确认、预览标题/正文/图片入口、关闭和明确打开、临时缓存、阅读/PO/历史不变、局部失败重试、慢请求取消、旧式页码/回复链接、嵌套窗口、深浅主题与浏览器回退。图片下载器和正文渲染器没有改动，不重跑图片、订阅或全文渲染套件，也未执行完整 EXE 窗口巡检。图片入口检查使用无图模式和固定数据，没有真实图片下载。

验收时重点尝试：读串途中点击串链接再关闭预览；点击板块蓝字后取消；确认打开带页码的串链接。三种操作应分别保持原位置、取消切换、进入指定页。编译、发布体积和检查记录见 [交付验证](verification.md)。
